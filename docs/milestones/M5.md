## Critical Historical Event

The first benchmark was rejected.

It produced impressive token reduction, but retrieval quality was not
acceptable:

- an important primary `config.py` was missed
- historical/generated report material was selected as noise

Therefore the favorable metric was not accepted as Exit Evidence.

The selector was refined by:

- strengthening exact-identifier weighting
- excluding generated/report directories
- improving retrieval precision

Only after that was the controlled A/B rerun and evidence frozen.

This is a key project lesson:

> Good metric != good system.

- deterministic retrieval before RAG/vector infrastructure
- selection reasoning must remain auditable
- reducing input is not sufficient if relevance regresses
